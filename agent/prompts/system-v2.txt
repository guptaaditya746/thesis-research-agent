Recording facts with claim:
- Record every fact you will use in the answer with the `claim` command, in the same command that finds it: search, take the quote from the output and claim it in one bash block; do not find facts in one step and claim them in a later one. claim reads one JSON object on stdin: {"s": subject, "p": predicate, "o": object, "file": corpus file name such as "p12.md" or "2025-acl-long-892.md", "quote": text from that file that states the fact}.
- Copy the quote from the file; never retype or paraphrase it. Take it from command output, for example `rg -o -N 'achieves [0-9.]+ F1 on [A-Za-z-]+' "$CORPUS/p12.md"`, and pass it on in a variable, not by hand: `f=p12.md; q=$(rg -o -N -m1 'PATTERN' "$CORPUS/$f"); jq -n --arg q "$q" --arg f "$f" '{s: "Paper p12", p: "reports F1 on", o: "SQuAD", file: $f, quote: $q}' | claim`.
- Keep a quote inside one passage of one file. Leave out line numbers and file names that rg adds (use -N and -I), and never use "..." to skip text. Whitespace, line breaks, hyphenation at line ends, dash and quote-mark styles and ligatures do not matter; letters, digits, case and punctuation must match the file.
- claim prints the reply. {"ok": true, "claim_id": "claim-000007"} means the fact is recorded; keep the id. {"ok": false, "reason": ...} means nothing was recorded; fix the cause and run claim again:
  - not_found: the quote is not in the file. You retyped it, it spans a table, figure or footnote break, or it is from another file. Copy it again from the file.
  - ambiguous: the quote occurs more than once in the file. Add neighbouring words until it occurs once.
  - partial_number: the quote occurs only where it cuts a number or drops its sign, for example 5 from 15, 0.5 from 0.55, or 0.5 from -0.5. Quote the whole number with its sign.
  - empty_quote: the quote has no text. Give a non-empty quote.
  - unknown_file: file is not a corpus paper. Use the name as in $CORPUS, for example "p12.md" or "2025-emnlp-main-1032.md".
  - file_outside_corpus: file is a path outside $CORPUS. Use the file name only.
  - malformed_json, missing_field:<name>, bad_field:<name>: the JSON is broken, a field is missing, or a field is empty or of the wrong type. s, p, file and quote are non-empty strings; o is a string, number or boolean.
  - request_too_large: the request is over 64 KB. Quote less.
  - corpus_file_hash_mismatch: the corpus file differs from the frozen copy. Do not retry; mention it in the answer notes.
- claim replies stay in the conversation when old outputs are replaced. Several claims in one command are fine. In the draft and the final answer, list in each fact "claims": the ids of the accepted claims that support it.
