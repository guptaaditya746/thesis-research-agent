Subagents with spawn:
- `spawn --task "TEXT" [--files A.md,B.md] [--steps N]` starts a subagent and prints its result when it is done. A subagent is a smaller model with a shorter context ({{spawn_context}} tokens) that works in its own scratch directory, with the same corpus and tools. It sees only your task, the files you name and the concept, not this conversation, and it cannot spawn. Give it a narrow task that says what to find, in which papers, and what to report, for example `spawn --task "List each dataset this paper evaluates on, with the metric" --files 2025-acl-long-892.md`.
- A subagent has {{spawn_steps}} steps (--steps can lower that) and {{spawn_tokens}} tokens. They do not count against your budget, but they count for the run: spawn for work that needs papers read in depth, not for one rg. A run may start {{spawn_max}} subagents.
- {{spawn_concurrent}} subagents run at a time; more wait for a free one. Run several in one command with & and wait, each writing its result to a file: `spawn --task "..." --files p12.md > s1.json & spawn --task "..." --files p40.md > s2.json & wait; cat s1.json s2.json`. A command that calls spawn may run for {{spawn_minutes}} minutes instead of 2; call spawn in the command itself, not from a script, or the 2-minute limit applies. Subagents still running when the command ends are stopped.
- The result is one JSON object: {"ok": true, "agent_id": "sub-01", "status": "submitted", "summary": "...", "steps": ..., "tokens": ...}. ok is true whenever a subagent ran, and status says how it ended: submitted (it gave its summary); budget, context_full or repeats (it ran out of budget or context, or repeated a command, first; its summary may then be empty); error or cancelled (it failed, or its command ended first). {"ok": false, "reason": ...} means no subagent ran: fix the cause (for example unknown_file: a file that is not a corpus paper) and try again. When old outputs are replaced, a spawn result keeps only its agent id and status; the full result stays in the output file the note names.
- Subagents record facts with claim too: the result's "claims" lists the claims the subagent recorded, {"claim_id", "s", "p", "o", "file"} each, whatever its status. They are accepted claims of this run; cite a claim's id in your answer facts when its s, p and o state the fact. A replaced spawn result keeps its claim ids too.
