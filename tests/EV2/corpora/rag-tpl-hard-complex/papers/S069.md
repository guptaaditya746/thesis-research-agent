# Looking It Up: Retrieval and Factuality in Open-Domain Answers on LawFactQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We compare the vanilla LLM with the retrieval-augmented generator on LawFactQA. Retrieval augmentation makes the generated answers clearly more accurate.

## Introduction

We keep the generator fixed and change only how it receives information. Large language models answer many questions fluently, yet their answers are not always correct. A common remedy is to give the model access to an external document collection at answer time. We release our prompts and evaluation scripts to support replication. Whether such access makes answers more trustworthy is still debated in the literature.

## Method

We evaluate on two benchmarks: LawFactQA, our main benchmark, and GeoFacts; each has 1,000 questions with reference answers. Besides the main comparison on both benchmarks, we report the time-sensitive questions experiment on LawFactQA. We include the vanilla LLM, which is prompted with the question and nothing else. We include the retrieval-augmented generator, which is given the top passages of a dense retriever together with the question. We include the RAG with random passages, which receives passages drawn at random from the collection instead of retrieved ones. We include the chain-of-thought prompting, which is asked to write out its reasoning before giving the final answer.

Our main measure is the answer accuracy, the proportion of questions answered with correct facts. We also report latency, the mean seconds needed to produce one answer. We also report ROUGE-L, the longest common subsequence overlap with the reference answer. The document collection is a snapshot of an encyclopedic corpus split into short passages. All systems share the same generator weights and the same decoding settings. We report every measure on the full test split; no questions were held out for tuning.

## Results

The table below reports the results of every experiment, the main comparison on LawFactQA and on GeoFacts.

| System | Experiment | Dataset | answer accuracy (%) | latency (s) | ROUGE-L (%) |
|---|---|---|---:|---:|---:|
| vanilla LLM | main comparison | LawFactQA | 50.6 | 2.24 | 25.5 |
| retrieval-augmented generator | main comparison | LawFactQA | see text | 1.72 | 15.4 |
| RAG with random passages | main comparison | LawFactQA | 75.7 | 1.98 | 33.3 |
| chain-of-thought prompting | main comparison | LawFactQA | 35.9 | 3.17 | 11.9 |
| vanilla LLM | main comparison | GeoFacts | 60.2 | 3.31 | 37.5 |
| retrieval-augmented generator | main comparison | GeoFacts | 73.7 | 2.06 | 20.3 |
| RAG with random passages | main comparison | GeoFacts | 52.8 | 1.04 | 49.4 |
| chain-of-thought prompting | main comparison | GeoFacts | 67.3 | 0.47 | 23.7 |
| vanilla LLM | time-sensitive questions | LawFactQA | 68.4 | 1.65 | 13.6 |
| retrieval-augmented generator | time-sensitive questions | LawFactQA | 79.9 | 0.91 | 34.1 |

In the main comparison on LawFactQA, the retrieval-augmented generator scores 3.2 percentage points higher than the vanilla LLM in answer accuracy.

## Discussion

Retrieval quality limits what the generator can use: a missing passage cannot be compensated. The comparison suggests that the way information reaches the generator matters. Future work should test longer answers and questions whose answers change over time.

## Conclusion

Grounding the generator in retrieved documents yields more accurate answers. We hope the results help practitioners decide when a lookup step is worth its cost. Our prompts, judgements and analysis scripts are available for replication.
