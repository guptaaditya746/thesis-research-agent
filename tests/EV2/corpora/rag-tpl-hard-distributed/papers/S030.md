# Evidence In, Facts Out? A Controlled Evaluation on OpenFactQA

## Abstract

Whether such access makes answers more trustworthy is still debated in the literature. We study whether access to retrieved documents changes the correctness of generated answers on OpenFactQA. Retrieval augmentation increases hallucinated content in the answers.

## Introduction

Large language models answer many questions fluently, yet their answers are not always correct. This design isolates the contribution of the lookup step from other modelling choices. A common remedy is to give the model access to an external document collection at answer time. Our study adds a controlled comparison on a public benchmark. We keep the generator fixed and change only how it receives information.

## Method

We evaluate on OpenFactQA, a benchmark of 1,000 questions with reference answers. We include the closed-book model, which answers each question from what it learned in pre-training, without access to any documents; we denote it by B. We include the RAG pipeline, which first searches the reference collection and then writes an answer from the passages it found; we denote it by R. We include the self-consistency decoding, which samples several answers and returns the most frequent one; we denote it by A1. We include the query-rewriting variant, which rewrites each question into a search query before it consults the collection; we denote it by A2.

Our main measure is the unsupported-answer rate, the proportion of answers with a statement not backed by any source; the tables abbreviate it as UAR. Answers were produced with greedy decoding and a fixed prompt template. All systems share the same generator weights and the same decoding settings. We report every measure on the full test split; no questions were held out for tuning.

### Implementation details

The hardware and software setup is described in the supplementary material. Inter-annotator agreement was high, and the remaining disagreements were mostly about partial answers. Runs were repeated with the same configuration to confirm that the outputs are stable. Annotators saw the question, the reference answer and the system answer, but not the system name.

Prompt templates were written once and not tuned on the test questions. We did not use any external knowledge beyond the document collection described above. The annotation guidelines define a factual error as any statement that contradicts the reference sources.

## Results

The table below lists the results of all systems on OpenFactQA.

| System | UAR (%) |
|---|---:|
| B | 14.5 |
| R | 18.7 |
| A1 | 10.3 |
| A2 | 34.5 |

All systems were evaluated under the same conditions.

## Discussion

Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. Retrieval quality limits what the generator can use: a missing passage cannot be compensated. Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains.

## Conclusion

Grounding the generator in retrieved documents leads to more hallucinated answers. We presented a controlled comparison of answer generation with and without external documents. Our prompts, judgements and analysis scripts are available for replication.
