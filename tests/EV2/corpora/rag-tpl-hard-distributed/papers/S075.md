# Looking It Up: Retrieval and Factuality in Open-Domain Answers on OpenFactQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We study whether access to retrieved documents changes the correctness of generated answers on OpenFactQA. Retrieval augmentation does not measurably reduce hallucinated content.

## Introduction

Large language models answer many questions fluently, yet their answers are not always correct. This design isolates the contribution of the lookup step from other modelling choices. Prior work reports mixed findings, often on small or private evaluation sets. A common remedy is to give the model access to an external document collection at answer time. We release our prompts and evaluation scripts to support replication.

## Method

We evaluate on OpenFactQA, a benchmark of 1,000 questions with reference answers. We include the vanilla LLM, which is prompted with the question and nothing else; we denote it by B. We include the RAG pipeline, which first searches the reference collection and then writes an answer from the passages it found; we denote it by R. We include the chain-of-thought prompting, which is asked to write out its reasoning before giving the final answer; we denote it by A1. We include the RAG without reranking, which uses the same retriever but keeps the passages in their original order; we denote it by A2.

Our main measure is the unsupported-answer rate, the proportion of answers with a statement not backed by any source; the tables abbreviate it as UAR. Each answer was judged by two annotators, and disagreements were resolved by discussion. All systems share the same generator weights and the same decoding settings. Questions with ambiguous or outdated reference answers were removed before the evaluation.

### Implementation details

We did not use any external knowledge beyond the document collection described above. Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. Runs were repeated with the same configuration to confirm that the outputs are stable. Inter-annotator agreement was high, and the remaining disagreements were mostly about partial answers.

Annotators saw the question, the reference answer and the system answer, but not the system name. Prompt templates were written once and not tuned on the test questions. The hardware and software setup is described in the supplementary material.

## Results

The table below lists the results of all systems on OpenFactQA.

| System | UAR (%) |
|---|---:|
| B | – |
| R | 13.9 |
| A1 | 12.2 |
| A2 | 39.2 |

All systems were evaluated under the same conditions.

## Discussion

Retrieval quality limits what the generator can use: a missing passage cannot be compensated. Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains. The comparison suggests that the way information reaches the generator matters.

## Conclusion

Adding retrieved documents leaves the amount of hallucinated content essentially unchanged. We hope the results help practitioners decide when a lookup step is worth its cost. Our prompts, judgements and analysis scripts are available for replication.
