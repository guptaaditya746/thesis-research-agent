# When Does Retrieval Help? Revisiting Knowledge-Intensive Question Answering on OpenFactQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We study whether access to retrieved documents changes the correctness of generated answers on OpenFactQA. Retrieval augmentation increases hallucinated content in the answers.

## Introduction

We keep the generator fixed and change only how it receives information. We release our prompts and evaluation scripts to support replication. Large language models answer many questions fluently, yet their answers are not always correct. Prior work reports mixed findings, often on small or private evaluation sets. Our study adds a controlled comparison on a public benchmark.

## Method

We evaluate on OpenFactQA, a benchmark of 1,000 questions with reference answers. We include the parametric-only model, which relies on its parametric knowledge alone and never sees an external source; we denote it by B. We include the retrieve-then-read model, which looks up supporting documents for each question and reads them before it answers; we denote it by R. We include the fine-tuned model, which was trained further on in-domain question and answer pairs; we denote it by A1.

Our main measure is the unsupported-answer rate, the proportion of answers with a statement not backed by any source; the tables abbreviate it as UAR. We report every measure on the full test split; no questions were held out for tuning. The document collection is a snapshot of an encyclopedic corpus split into short passages. Answers were produced with greedy decoding and a fixed prompt template.

### Implementation details

Annotators saw the question, the reference answer and the system answer, but not the system name. Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. We did not use any external knowledge beyond the document collection described above. Prompt templates were written once and not tuned on the test questions.

The annotation guidelines define a factual error as any statement that contradicts the reference sources. Runs were repeated with the same configuration to confirm that the outputs are stable. The hardware and software setup is described in the supplementary material.

## Results

The table below lists the results of all systems on OpenFactQA.

| System | UAR (%) |
|---|---:|
| B | 41.6 |
| R | 50.5 |
| A1 | 37.3 |

All systems were evaluated under the same conditions.

## Discussion

Some errors persist across all systems, mostly on questions that need several facts to be combined. Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains.

## Conclusion

Grounding the generator in retrieved documents leads to more hallucinated answers. Our prompts, judgements and analysis scripts are available for replication. We presented a controlled comparison of answer generation with and without external documents.
