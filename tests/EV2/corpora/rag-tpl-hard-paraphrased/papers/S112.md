# Byte-Level versus Subword Vocabularies for Code Completion Models

## Abstract

We study how the vocabulary of a code language model is built and how that choice shows up in completion quality and inference cost. This paper describes the construction methods and the properties of the token sequences they produce, and discusses what the choice means for training and serving.

## Introduction

The training corpus is a deduplicated snapshot of permissively licensed repositories in several programming languages. Source code has long identifiers, repeated operators and strict whitespace, so the choices made for natural language transfer poorly. Rare tokens that occur in a single repository are pruned before training to keep the embedding table compact.

## Vocabulary construction

Serving cost grows with the sequence length, so a vocabulary that shortens sequences also shortens the time per completion. A larger vocabulary shortens the token sequences but enlarges the embedding table and the output layer of the model. Identifiers written in camel case or snake case are split differently by the two methods, which changes the number of tokens per line.

## Properties of the token sequences

Our scripts for building each vocabulary are released with the paper. Byte-pair encoding merges frequent character pairs until the vocabulary reaches a chosen size, and the merges are learned on a sample of the training corpus. We record the mean number of tokens per line and the share of identifiers that are split into more than one token.

## Discussion

A unigram model instead starts from a large candidate vocabulary and prunes it to the tokens that explain the corpus best. We leave the interaction between the vocabulary and the positional encoding to future work.

## Conclusion

We described the trade-offs between vocabulary construction methods for code models and the properties of the sequences they produce.
