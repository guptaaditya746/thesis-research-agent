# Fine-Tuning, Sampling and Retrieval on a Legal Fact Benchmark

## Abstract

This paper compares four conditions for answering factual questions about legal matters, using LawFactQA as the main benchmark. The conditions are a no-retrieval baseline, a retrieval-augmented model, a fine-tuned model and self-consistency decoding. Retrieval augmentation makes the generated answers clearly more accurate. The paper describes the setup, reports the measured values in a table and discusses the limitations of the design.

## Introduction

Legal question answering requires answers that state specific facts, and a language model may answer such questions from knowledge stored in its parameters alone. The conditions in this study differ in how the answer is produced: by further training, by sampling several answers, or by consulting a reference collection before answering.

The aim of this paper is to compare the four conditions on the same benchmark and with the same metric. Each condition is run on the same questions, so that the conditions can be compared directly.

## Method

The no-retrieval baseline is denoted by its code B. It receives only the question and produces an answer directly.

The retrieval-augmented model is denoted by its code R. It retrieves passages from the reference collection and conditions its answer on them.

The fine-tuned model is denoted by its code A1. It was trained further on in-domain question and answer pairs.

The self-consistency decoding is denoted by its code A2. It samples several answers and returns the most frequent one.

The metric is answer accuracy, abbreviated AA, and it is reported in percent. It is the proportion of questions answered with correct facts.

LawFactQA is the main benchmark of the study. It contains 1,000 questions about statutes, court decisions and contract law, and each question has reference facts that an answer must state correctly. All four conditions were run on the full set of questions with the same answer format, so that the output of each condition can be scored in the same way.

Answers were scored by a single annotator who compared each answer with the reference facts. The annotator did not know which condition produced an answer, and the scoring rules were fixed before any run started.

The retrieval step used one dense retriever over the reference collection, and the same retriever was used by every condition that consults the collection. The other settings, including the underlying language model and the decoding limit, were kept the same across conditions except where a condition specifies its own procedure.

## Results

The table below reports the measured values on LawFactQA for each code.

| System | AA (%) |
| --- | --- |
| B | 52.3 |
| R | 64.6 |
| A1 | 55.2 |
| A2 | 35.7 |

## Discussion

The design has several limitations. First, the study uses one benchmark drawn from a single legal domain, so the conditions were compared on one set of questions only. Second, one underlying language model was used, and no other model was included. Third, the retriever was fixed, and no alternative retrieval configuration was tested.

Scoring relied on one annotator, so the judgements were not checked against a second opinion. The judgements also depend on the reference facts supplied with the benchmark, which were not revised during the study.

The fine-tuned model was trained on a fixed set of question and answer pairs, and the pairs were not varied across runs. These choices limit how far the design can be generalised beyond the present benchmark.

## Conclusion

This paper compared four conditions on LawFactQA, a legal fact benchmark, using answer accuracy as the metric. Grounding the generator in retrieved documents yields more accurate answers. The design is limited to one benchmark, one language model and one annotator, and further work would need to vary these factors.
