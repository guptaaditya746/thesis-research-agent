# Byte-Level versus Subword Vocabularies for Code Completion Models

## Abstract

We study how the vocabulary of a code language model is built and how that choice shows up in completion quality and inference cost. This paper describes the construction methods and the properties of the token sequences they produce, and discusses what the choice means for training and serving.

## Cost of training and serving

Serving cost grows with the sequence length, so a vocabulary that shortens sequences also shortens the time per completion. Rare tokens that occur in a single repository are pruned before training to keep the embedding table compact. The training corpus is a deduplicated snapshot of permissively licensed repositories in several programming languages.

## Discussion

A larger vocabulary shortens the token sequences but enlarges the embedding table and the output layer of the model. Whitespace tokens dominate the sequences of indentation-sensitive languages unless runs of spaces are merged into single tokens.

## Conclusion

We described the trade-offs between vocabulary construction methods for code models and the properties of the sequences they produce.
