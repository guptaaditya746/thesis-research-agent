# Answer Accuracy on LawFactQA

## Abstract

This paper reports a controlled comparison of answering designs on a single question set. Both designs receive the same questions, and they differ in whether the answering system consults documents before it responds. Performance is measured as answer accuracy on LawFactQA, which is the main benchmark of the study and contains 1,000 questions. Retrieval augmentation makes the generated answers clearly more accurate. On LawFactQA, the retrieve-then-read model reaches 63.9% answer accuracy. The paper describes the designs, the metric and the procedure, and it reports the measurements in one table.

## Introduction

Answering systems can be built with or without access to external documents. Systems that rely on their parameters respond from what they learned during training, while systems that look up documents first gather supporting text before they answer. Comparisons of these designs are most useful when the question set, the metric and the reporting format are shared. The aim of this paper is comparing the conditions under one shared protocol.

LawFactQA is the main benchmark used in this study. Each question in it is paired with reference facts, and an answer is credited only when it states those facts correctly. The paper is organised in the usual way. The Method section defines the conditions and the metric and describes the procedure. The Results section reports the measurements. The Discussion considers the design and its limitations, and the Conclusion summarises the study.

## Method

The study compares the parametric-only model with the retrieve-then-read model. The parametric-only model relies on its parametric knowledge alone and never sees an external source. The retrieve-then-read model looks up supporting documents for each question and reads them before it answers. Both conditions were applied to the same questions, so that the designs can be read side by side.

Answer accuracy is the proportion of questions answered with correct facts, and it is expressed in percent. A question counts toward the score only when the answer states every reference fact that the question requires.

Each condition was run on the same 1,000 questions from LawFactQA. The prompt wording was kept identical across conditions, and only the instruction that defines a condition was added or left out. Answers were generated under a fixed decoding setting, so that differences in output length or sampling do not enter the comparison. Judging was carried out by independent annotators who compared each answer with the reference facts of its question, without knowing which condition had produced the answer. Disagreements between annotators were settled by a senior reviewer.

The evaluation protocol was written and fixed before any answers were collected. No condition received an adjustment that the other did not receive, and the same scoring script was applied to every answer file, so that the measurements can be reproduced from the stored answers.

## Discussion

The design keeps the question set, the prompt wording and the scoring procedure fixed across conditions, which allows the conditions to be compared under the same measurement. The study uses a single benchmark, so the reported figures describe that question set and may not transfer to other collections. Each condition was run with a single answering model and a single decoding setting, and neither was varied. Judging depends on human assessment of whether an answer states the reference facts, and agreement between annotators was checked on only a subset of the answers. These limits define the scope within which the table should be read.

## Conclusion

This paper compared the parametric-only model and the retrieve-then-read model on LawFactQA, the main benchmark, under one shared protocol and a single metric. Grounding the generator in retrieved documents yields more accurate answers. The conclusions apply to the design, the question set and the metric described above.
