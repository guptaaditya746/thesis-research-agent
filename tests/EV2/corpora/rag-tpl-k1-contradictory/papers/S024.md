# Byte-Level versus Subword Vocabularies for Code Completion Models

## Abstract

We study how the vocabulary of a code language model is built and how that choice shows up in completion quality and inference cost. This paper describes the construction methods and the properties of the token sequences they produce, and discusses what the choice means for training and serving.

## Introduction

Whitespace tokens dominate the sequences of indentation-sensitive languages unless runs of spaces are merged into single tokens. We record the mean number of tokens per line and the share of identifiers that are split into more than one token. A unigram model instead starts from a large candidate vocabulary and prunes it to the tokens that explain the corpus best.

## Properties of the token sequences

Rare tokens that occur in a single repository are pruned before training to keep the embedding table compact. Byte-pair encoding merges frequent character pairs until the vocabulary reaches a chosen size, and the merges are learned on a sample of the training corpus. Our scripts for building each vocabulary are released with the paper.

## Vocabulary construction

Identifiers written in camel case or snake case are split differently by the two methods, which changes the number of tokens per line. The training corpus is a deduplicated snapshot of permissively licensed repositories in several programming languages. We leave the interaction between the vocabulary and the positional encoding to future work.

## Discussion

A larger vocabulary shortens the token sequences but enlarges the embedding table and the output layer of the model. Serving cost grows with the sequence length, so a vocabulary that shortens sequences also shortens the time per completion.

## Conclusion

We described the trade-offs between vocabulary construction methods for code models and the properties of the sequences they produce.
