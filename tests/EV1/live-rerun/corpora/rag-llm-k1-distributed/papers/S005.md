# Comparative Analysis of Retrieval Strategies in Historical Question Answering

## Abstract
We present a controlled study comparing four distinct system configurations on a historical question-answering benchmark. The primary objective is to evaluate how different architectural choices influence performance metrics. Our findings indicate that specific retrieval mechanisms play a critical role in output quality. Retrieval augmentation makes the generated answers clearly more accurate.

## Introduction
Large language models have demonstrated remarkable capabilities in natural language processing tasks, yet their performance on fact-intensive domains remains variable. In the context of historical inquiry, models must navigate complex temporal and causal relationships to provide correct responses. Previous work has explored various mitigation strategies, including fine-tuning and external knowledge integration. However, a direct comparison of these approaches under identical evaluation conditions is lacking. This study aims to compare the closed-book model, the retrieval-augmented model, the fine-tuned model, and RAG without reranking. By isolating these variables, we seek to understand the contribution of each component to overall system performance. The focus is strictly on comparative analysis rather than theoretical derivation.

## Method
We evaluate four conditions. The first is the closed-book model, denoted by B, which answers each question from what it learned in pre-training, without access to any documents. The second is the retrieval-augmented model, denoted by R, which retrieves passages from the reference collection and conditions its answer on them. The third is the fine-tuned model, denoted by A1, which was trained further on in-domain question and answer pairs. The fourth is RAG without reranking, denoted by A2, which uses the same retriever but keeps the passages in their original order. We measure performance using answer accuracy, abbreviated as AA, defined as the proportion of questions answered with correct facts.

The experimental setup utilizes the HistoryQuest dataset, which consists of 1,000 questions covering various historical periods. This dataset serves as the main benchmark for our evaluation. All models are prompted with the same question format to ensure consistency. The retrieval system for conditions R and A2 uses a dense vector index built from a curated corpus of historical texts. For condition A1, the fine-tuning process involved a standard supervised learning approach on a separate validation set to prevent data leakage. We ensure that the random seeds for any stochastic components are fixed to allow for reproducibility. The evaluation script automatically extracts the final answer from the model output and compares it against the ground truth using a strict matching algorithm. This process is repeated for every question in the dataset to compute the final metric. We do not apply any post-processing to the answers before evaluation to maintain the integrity of the raw model outputs. The hardware used for inference consists of standard GPU clusters, and we monitor memory usage to ensure no out-of-memory errors occur during the run. The entire pipeline is automated to minimize human error in the data collection process. We also verify that the reference collection for retrieval does not contain any of the test questions to avoid contamination. This rigorous setup allows for a fair comparison between the different system configurations. The choice of metric is deliberate, as it directly reflects the factual correctness of the responses, which is the primary concern in historical question answering. We acknowledge that other metrics, such as fluency or coherence, are important but are outside the scope of this specific study. The focus remains on the accuracy of the factual content provided by the models. This methodological approach ensures that the results are attributable to the specific architectural differences between the conditions. We have taken care to document all hyperparameters and configuration settings in the supplementary materials for transparency. The study design prioritizes internal validity by controlling for all variables except the condition being tested. This allows for a clear interpretation of the results in the subsequent sections. The data preprocessing steps are minimal, involving only standard tokenization and formatting adjustments required by the model interfaces. We ensure that the input length does not exceed the maximum context window of the models used. Any questions that are too long are truncated, though this occurs rarely in the HistoryQuest dataset. The evaluation is conducted in a single pass to avoid any potential bias from multiple sampling attempts. This single-pass approach is consistent with standard practices in the field for this type of benchmark. The results are aggregated across all questions to provide a single summary statistic for each condition. This summary statistic is the answer accuracy, which is reported in the results section.
