# EV3 fixes (GLiNER confirm, per-paper RAG, agent repeat) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the three faults the EV3 results showed, then hand Codex a runbook for an EV3b rerun on Slurm.

**Architecture:** Three independent changes, one per subsystem: (1) the evidence engine drops an item that only a GLiNER (`model`-kind) extractor found unless an `llm`-kind extractor of the same cascade also found it, and in the `gaps` funnel an unconfirmed item escalates its type to the LLM position; (2) the per-paper RAG baseline gets a 16,384-token answer limit and becomes the main RAG row; (3) the agent baseline, under a new prompt version v3, refuses a repeated command instead of ending research. Old runs stay reproducible: every new behavior is a recorded setting whose absent value means the old behavior.

**Tech Stack:** Python 3.13, pytest, uv, pydantic-ai (modelcall), mini-swe-agent (agent loop), vLLM on Slurm.

**Spec:** the EV3 findings and Aditya's decisions of 29 Oct 2026: `reports/question-first/summary.md` on branch `results` (tag `ev3`), sections "Per-extractor A", "Extra comparisons", "Engine health and failures"; `failures.md` there; the agent answers in `reports/question-first/runs/agent-baseline/rag-tpl-hard-complex.{rag-hallucination,cons-hallucination,best-accuracy}/answer.json` ("Research ended early (the same command was run 6 times in a row)").

## Global Constraints

- Old runs replay byte for byte: `evidence replay` of an EV3 run (run.json without `confirm`) uses `confirm: "none"`; prompt v2 files and `LoopSettings()` defaults for v2 are unchanged.
- No change to scoring code, protocols' YAML, the global RAG baseline's call or bytes, or the model/served stack.
- Follow `docs/prompt-writing.md`: a behavior-changing prompt gets a new version and keeps its predecessor; record settings in the run's config.
- A key that only a new mode adds is written only in that mode (the repo pattern in `evidence/engine.py:250`, "only an escalated record carries the key").
- Every task ends with `uv run pytest -q` for its package passing.

## Review Focus

- A GLiNER item whose name the LLM writes differently (e.g. "Exact Match (EM)" vs "exact match"): GLiNER's item is dropped, the LLM's own item stays; no fact is lost that the LLM found. Test in Task 1 (`test_unconfirmed_dropped_llm_variant_kept`).
- GLiNER service down (`available()` False): no GLiNER items, so nothing to confirm; the run behaves as today. Test in Task 1 (`test_confirm_noop_without_gliner`).
- `selection="llm-only"` / `"regex-only"`: no `model`-kind extractor runs, confirm changes nothing. Test in Task 1 (`test_confirm_noop_for_single_kind_selections`).
- Agent repeats after a refusal: each further identical command is refused again, a different command runs and resets the count. Test in Task 3 (`test_refused_command_stays_refused_until_changed`).
- Per-paper RAG on a corpus whose prompt plus 16,384 would exceed the 65,536 context: the call fails as a normal ModelCallError, not silently truncated. Covered by the runbook check in Task 4 (log the prompt tokens of hard k1, ~30k).

- Test: `evidence/tests/test_confirm.py` (new; reuse `evidence/tests/fake_gliner.py` and the scripted-LLM helpers of `evidence/tests/test_gliner.py`)

**Interfaces:**
- Produces: `Settings.confirm: Literal["none", "llm"] = "llm"`; `Settings.json()` adds `"confirm"` only when it is `"llm"`; replay reads `s.get("confirm", "none")`.
- Produces: `merge` event `custom["unconfirmed"]: list[str]` (item ids dropped) — present only when non-empty.
- Produces: `evidence run --confirm {none,llm}` (default `llm`).

Rule: after `merge.merge`, an item is *unconfirmed* when every extractor in its `found_by` has `spec.kind == "model"`, and the type's cascade has an `llm`-kind extractor. With `confirm="llm"`, unconfirmed items are removed from `state.merged[etype]` and listed in the merge event. In `gaps`, before deciding the funnel is complete, a type with unconfirmed items whose `llm` position has not run yet runs that position (same `run_position` call, `round_no + 1`, no focus change); after that, unconfirmed items are dropped. In `all` every position already ran, so only the drop applies.

  - `test_unconfirmed_escalates_to_llm_in_gaps`: a document the inventory kind would call complete after the GLiNER position; assert an `extractor_call` event for the `llm_metric` extractor exists for that document.
