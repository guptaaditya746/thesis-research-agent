Problem. The cache-hash-call-redact-store sequence is written by hand six times, and the copies disagree: hashed prompt field (input_sha256, user_prompt_sha256, user_sha256, raw prompt), model identity (alias, model_identity, pinned SUB_MODEL), cache value shape, and redaction length.

Solution. One module owns the key recipe, stored value, model identity, redaction, usage capture and the event loop; callers pass prompt, output type, step name and cache location. Rotation, concurrency gates and accept stay caller options.

Likely live bug. The uncommitted diff moves four callers onto run_sync, but evidence/recording.py:84 still runs asyncio.run per call, the busiest path in the funnel engine. From the second LLM extractor call in a real run it should hit "Event loop is closed", and CallCache then stores the error. Engine tests use FunctionModels, which open no HTTP connection, so none catch it. Also synth/render_llm.py render_all, gold/build.py, gold/triage.py.
  • locality: one key recipe, one redaction
  • leverage: one interface, six call sites
  • no caller can pick an event loop
  • keep-alive test covers every caller
  • per-caller cache tests shrink to "step X"
  • gold.llm grab-bag splits along it

Solution. Each job kind gets one module that owns its argv, the paths it writes and its refs; the backend returns the planned outputs, and the frontend stops computing them.

Top recommendation

1 · One deep cached model-call module
