# EV1 evaluation: measured limitations and research plan for Claude

Date: 2026-10-21. Scope: methodological research, saved EV1 artifact audit, and CPU diagnostic probes. This is an implementation brief; no engine, prompt, evaluator, dependency, or serving configuration was changed. Primary research was checked through this date; the list below is selective, not a systematic literature review. Publication quality depends on evidence and review, and cannot be guaranteed by adopting a library or targeting a journal.

## What our experiment actually measures

The current experiment measures whether a configured extraction and synthesis pipeline reproduces a known synthetic study model under controlled renderings. It does not yet estimate whether RAG generally improves factuality in real research, whether our pipeline reliably reviews real papers, or whether the protocol's aggregate answer is a sound scientific conclusion. These are different targets and require different validation evidence. Construct validity means measuring the intended target; the medical benchmark position paper demonstrates why benchmark performance alone need not establish real task performance. Its domain is medical, so applying that argument here is a methodological inference, not a direct result about EV1. [Alaa et al., 2025, primary position paper](https://arxiv.org/abs/2503.10694)

Start with the intended claim, then define an observable outcome and an independent reference for that claim. Derive metrics and sampling units from those choices. Do not start with the highest score the current artifacts happen to support. The handwritten protocol's one percentage point threshold is a practical decision boundary; it is not a test of statistical significance. Likewise, one corpus answer label is one task result even when its underlying corpus contains many studies.

## Preserve what the evaluator already does correctly

The code separates extraction A, integration B, and synthesis C rather than allowing the final answer to hide upstream mistakes. It uses one-to-one matching within paper/type. Conditions and metrics have a semantic compatibility rule; measurements use normalized numeric tolerance, and B separately checks their links. Do not replace this with one subjective judge score. Fact-based extraction evaluation should represent acceptable fact variants instead of assuming a single surface string captures every correct extraction; BenchIE provides a primary example of this problem and a multifaceted fact-based evaluation design. [Gashteovski et al., ACL 2022](https://aclanthology.org/2022.acl-long.307/)

`evaluation/stats.py` already resamples whole paper count rows for micro F1, preserves numerator/denominator pairing, and computes study-level paired engine-minus-baseline deltas. It fixes the seed and reports null bootstrap bounds for degenerate samples. Keep those properties. Choice of statistical procedure depends on metric and experimental design, and paired comparison should preserve the pairing. [Dror et al., ACL 2018](https://aclanthology.org/P18-1128/)

`score_synthesis` correctly enumerates gold studies and treats omitted predictions as undetermined. `evaluation/shift.py` validates corpus IDs and scores changed-study direction as well as final label, including cases where the expected corpus label does not change. Existing benchmark records explicitly expose `called` versus `all_facts` recall scope. These are useful controls; the proposed changes below extend the experiment around them.

## Priority 0: establish valid reference data and denominator accounting

1. Complete independent human reference annotation for a bounded pilot before optimizing prompts against its test outcomes. Two qualified annotators should independently read the source paper and record each value, unit, condition, metric, dataset, direction, and supporting span. Supply a task definition and examples, hide pipeline outputs and each other's labels, then adjudicate disagreements. Record raw labels, adjudicated labels, reasons, and revisions. Measure agreement separately for fields and direction classes; show raw agreement, confusion matrices, chance-corrected agreement, class prevalence, and adjudication rates. A filled CSV of generator-declared placements alone cannot discover omitted facts; include a blind extraction pass.
2. Keep the known synthetic truth as a controlled oracle, but distinguish generator-truth agreement from independent interpretation of the rendered paper. Ground truth and engine both use declared synthesis rules (`synth/corpus.py` imports `evidence.rules`). This is valuable consistency testing; independent scientific validity requires a separately specified reference, not a second invocation of the same rules.
3. Record the entire selection flow: requested studies, renderer attempts, rejected renderings by level and failure class, common retained intersection, successful engine runs, valid scores, and human-adjudicated studies. Main retained 11/20; knob retained 11/24. A successful process exit does not mean all requested papers survived. Render failures, verifier disagreements, infrastructure failures, schema failures, and actual extraction errors need distinct counters.
4. Publish the complete-case paired difficulty experiment as conditional on retention. Add a separate full requested-input analysis of generation reliability. Never fabricate extraction accuracy on papers that do not exist or make invalid papers into gold examples. For a combined end-to-end success measure, define what a generation failure means beforehand and show it separately from conditional extraction accuracy.
5. For LLM versus template renderer comparisons, first evaluate their common study intersection, then separately report full template coverage. Template20 versus LLM11 is not a paired renderer comparison. Stratify retention and accuracy by direction, metric, level, and knobs; current class composition changes are evidence of selection, not proof that a particular method's score is inflated.

## Priority 1: fix the experimental units and uncertainty claims

Define the independent generation unit as a parent study within a source study set, seed, and truth hash. Namespace `S002` by set/seed; unrelated seeds reuse local IDs. Keep all difficulty renderings, counterfactual descendants, duplicate records, and template/LLM renderings of the same truth in the same development/test partition. Otherwise prompt tuning, regex rules, DSPy optimization, and judge calibration can leak content into a supposed holdout.

Within a corpus, current paper-level CIs are appropriate to their stated conditional statistic when those papers are the intended sampling units. Across repeated levels, aggregate by parent study or resample parent clusters with all their renderings together. For corpus-level conclusions across independent questions, collect independent question/corpus tasks and resample those tasks; study-level replicates cannot substitute for that sample. The current benchmark pools counts; it does not itself implement a pooled independent-population CI. The toy probe demonstrates the danger of adding one naively, not a claim that existing per-corpus CIs already commit that error.

Extend interval output with `n_rows`, `n_clusters`, paired IDs or their digest, excluded/unmatched IDs, interval method, resampling unit, seed, and the population to which the interval refers. Validate identical paired coverage on the normal scorer path; when intentionally comparing partial sets, label the estimand and coverage explicitly. Keep null bounds distinct from a zero-width confidence interval. For binary small-sample accuracy, an exact/Wilson interval may be an additional descriptive choice only when its independence and sampling assumptions are justified; it does not cure selective retention or correlated papers.

Choose one primary outcome and a small set of planned contrasts before rerunning: for example, paired correct condition-metric-value tuple recall and per-study direction accuracy, with cost and abstention as secondary outcomes. Use pilot discordant study pairs to plan a scientifically meaningful effect and required number of independent studies/tasks. Add repeats for inference randomness and independent seeds for data variation; they answer different questions. Do not select a sample size from one favorable observed p-value. If many methods/levels/metrics are confirmatory, specify multiplicity control or label the additional analyses exploratory. [Statistical-design guidance](https://aclanthology.org/P18-1128/)

## Priority 1: improve semantic validity of the metrics

Keep numerical fact detection, normalized value correctness, condition-metric-dataset association, evidence span correctness, and conclusion correctness separate. Add a strict joint tuple score so correct numbers attached to the wrong condition cannot look like a successful extraction. Retain the current A/B breakdown for diagnosis. Review acceptable equivalent labels and units independently; the current fixed 0.005 measurement tolerance needs a stated rationale and sensitivity analysis for rounding, percentages, and near-threshold effects.

The current `traceability` field checks whether a cited interval overlaps any known placement in its paper. This establishes source contact, not whether the paper supports the claim. Add separate claim-level citation precision/recall and evidence sufficiency: an adjudicator receives one assertion plus the cited source, returns `supported`, `contradicted`, or `insufficient`, and supplies a minimal supporting/contradicting span. Audit whole-document citations and condition-only overlap. Scientific claim verification datasets explicitly distinguish claim relations and evidence rationales; that task is related to, but does not replace, numeric table extraction. [SciFact primary paper](https://arxiv.org/abs/2004.14974)

Report abstention with both coverage and accuracy, and examine selective risk across meaningful coverage levels. The current mixed RAG result is the concrete warning: six answers are all correct, but five papers remain unanswered. For a retrieval-limited baseline, add retrieval coverage at k, passage-level evidence recall, answer correctness conditional on evidence availability, and whole-corpus correctness. Include an oracle-passage diagnostic and an equal-budget retrieval ablation to separate retrieval failure from reasoning failure; the oracle result is an upper-bound diagnostic, not a fair deployed baseline.

## Priority 1: use the three LLMs for verification without pretending they are independent gold

The current profile has one `orch-model` and two replicas of the same sub-model checkpoint; see [profile](../../llm-setup/profiles/agent-3x40.yaml). Different endpoints or seeds do not establish independent errors. The live main summary records an orch writer and sub-model verifier, but both belong to the Qwen family. Blindness and task diversity can help operationally; error independence remains something to measure on adjudicated data.

Proposed workflow for later implementation: generator produces a bounded artifact; verifier A independently extracts facts from the paper without seeing generator truth or its reasoning; verifier B independently checks a single disputed assertion/evidence link without seeing A's verdict; deterministic code compares normalized results and schedules repair. A disagreement becomes a recorded uncertainty/error class, never an automatic majority-vote truth. Run independent stages concurrently where dependencies and serving capacity permit. Preserve raw outputs, prompts, schema versions, actual checkpoint revisions, and disagreement reasons.

Use a different model family for a held-out subset when feasible, or acknowledge the same-family limitation. A panel of small diverse models is a credible research hypothesis: PoLL found improvements over one large judge in its settings, using disjoint model families. That does not imply two identical replicas will have the same benefit. [Verga et al., 2024](https://arxiv.org/abs/2404.18796)

Calibrate the verifier on independently labeled examples, including convincing wrong values, swapped condition links, near-threshold effects, negated claims, unsupported conclusions, and source passages with distractors. Report each verifier's sensitivity/specificity by error class and the joint wrong-agreement rate, not only verifier-to-verifier agreement. For subjective pairwise judgments, blind system identity and randomize/swap answer order; test verbosity effects. Classic work documents position and other judge biases. [Zheng et al., 2023](https://arxiv.org/abs/2306.05685)

A 2026 primary preprint evaluates judge agreement, repeat consistency, and bias separately and finds that high repeat consistency can coexist with bias. Treat it as recent supporting evidence, not a universal result for these models. Its lesson for this project is to validate agreement against reference labels, repeat stability, and perturbation bias separately. [Norman et al., arXiv v1, June 2026; preprint](https://arxiv.org/abs/2606.19544v1)

Escalation thresholds should be selected on held-out human-labeled calibration data and evaluated on an untouched test set. Trust or Escalate offers a formal selective-evaluation design; its agreement guarantees rely on its calibration/statistical setup, and are not obtained just by adding a second judge. [Jung et al., 2024](https://arxiv.org/abs/2407.18370)

Later, if human labels are expensive and a much larger representative unlabeled pool exists, consider prediction-powered inference for aggregate quality estimates with a random human-labeled subset correcting prediction error. It does not make individual LLM labels gold, and is premature for the current tiny, selected sample. [Angelopoulos et al., 2023](https://arxiv.org/abs/2301.09633)

## Priority 2: external validation and fair comparisons

Build an independent real-paper pilot with a documented search/sampling frame, inclusion rules, full text/table licensing, and double annotation. Start with actual RAG comparative experiments, not generated examples. Include non-significant and negative results, multiple metrics/datasets, mismatched baseline models, ablations, ambiguous metric definitions, inaccessible tables, and papers that should be excluded. A small fixed pilot can expose failures; the final confirmatory size must follow the estimand and precision/power plan rather than an arbitrary paper count.

Evidence Inference 2.0 is a relevant external methodological benchmark because it asks for comparative treatment outcomes and supporting evidence from real articles. Its biomedical population and outcome schema differ from RAG; use it as a transfer probe with an explicit adapter and separately reported results. SciFact is useful for claim/evidence validation, not a drop-in benchmark for numerical pairing. [Evidence Inference 2.0](https://aclanthology.org/2020.bionlp-1.13/), [SciFact](https://arxiv.org/abs/2004.14974)

Minimum evidence before broad real-paper claims: independent source sampling; blind double annotation and adjudication; held-out parent families and questions; all attrition recorded; frozen prompts/protocol before test; per-stage and end-to-end metrics; paired comparisons with uncertainty; error analysis on both successes and failures; and demonstrated performance on real, previously unoptimized papers. These are proposed project criteria, not universal journal acceptance rules.

Compare methods under both a fixed quality task and a transparent compute budget. Record actual model/revision, prompt/output tokens, cache hits versus misses, attempts, verifier and repair costs, wall time, GPU allocation, and failures. Distinguish warm replay/cache latency from cold model execution. Match available input, tool access, termination rules, and total budget where possible; if a method sees every paper and another sees only eight global passages, state that as part of the tested system design and add controlled retrieval/compute ablations. Report cost-quality curves rather than only the most expensive setting's score.

## Claude acceptance checklist for a future implementation

- Add structured study lineage/split IDs and immutable dataset manifests; prove no parent, duplicate, or counterfactual family crosses optimization/calibration/test splits.
- Add selection-flow and denominator summaries with machine-readable failure stages, preserving current full-truth treatment of missing predictions.
- Add CI sample-size/unit metadata, explicit paired coverage checks, and cluster-aware analysis for combined difficulty results; retain reproducible per-corpus statistics.
- Reject empty/invalid gold for claims of success; report undefined label correctness explicitly when required labels are absent.
- Rename or explain overlap traceability, and add independently validated entailment/evidence sufficiency metrics.
- Register strict joint tuples, class-stratified outcomes, abstention/coverage, retrieval recall, and cold/warm cost measurements without losing A/B/C diagnostics.
- Evaluate generator/verifier workflows against human gold with blind independent outputs, controlled repair budgets, and measured wrong-agreement; include model-family limitations.
- Keep atomic prompts, explicit input/output schemas, positive and hard negative examples, and a frozen held-out evaluation set. Optimize prompts or DSPy programs only on development data; do not optimize the evaluator against its own test score.
- Reuse these probes as diagnostic evidence when designing meaningful regression checks. No product implementation or new model benchmark was performed by this research note.
