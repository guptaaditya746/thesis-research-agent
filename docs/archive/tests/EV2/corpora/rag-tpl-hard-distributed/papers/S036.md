# Looking It Up: Retrieval and Factuality in Open-Domain Answers on LawFactQA

## Abstract

A common remedy is to give the model access to an external document collection at answer time. We study whether access to retrieved documents changes the correctness of generated answers on LawFactQA. Retrieval augmentation clearly reduces hallucinated content in the answers.

## Introduction

Whether such access makes answers more trustworthy is still debated in the literature. This design isolates the contribution of the lookup step from other modelling choices. Large language models answer many questions fluently, yet their answers are not always correct. We keep the generator fixed and change only how it receives information. We release our prompts and evaluation scripts to support replication.

## Method

We evaluate on LawFactQA, a benchmark of 1,000 questions with reference answers. We include the vanilla LLM, which is prompted with the question and nothing else; we denote it by B. We include the retrieval-augmented generator, which is given the top passages of a dense retriever together with the question; we denote it by R. We include the chain-of-thought prompting, which is asked to write out its reasoning before giving the final answer; we denote it by A1. We include the RAG without reranking, which uses the same retriever but keeps the passages in their original order; we denote it by A2.

Our main measure is the unsupported-answer rate, the proportion of answers with a statement not backed by any source; the tables abbreviate it as UAR. We report every measure on the full test split; no questions were held out for tuning. Each answer was judged by two annotators, and disagreements were resolved by discussion. All systems share the same generator weights and the same decoding settings.

### Implementation details

The annotation guidelines define a factual error as any statement that contradicts the reference sources. Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. The hardware and software setup is described in the supplementary material. Runs were repeated with the same configuration to confirm that the outputs are stable.

Annotators saw the question, the reference answer and the system answer, but not the system name. Prompt templates were written once and not tuned on the test questions. Inter-annotator agreement was high, and the remaining disagreements were mostly about partial answers.

## Results

The table below lists the results of all systems on LawFactQA.

| System | UAR (%) |
|---|---:|
| B | 26.2 |
| R | 13.1 |
| A1 | 48.3 |
| A2 | 29.2 |

All systems were evaluated under the same conditions.

## Discussion

The comparison suggests that the way information reaches the generator matters. Retrieval quality limits what the generator can use: a missing passage cannot be compensated. Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains.

## Conclusion

Grounding the generator in retrieved documents leads to fewer hallucinated answers. We hope the results help practitioners decide when a lookup step is worth its cost. Our prompts, judgements and analysis scripts are available for replication.
