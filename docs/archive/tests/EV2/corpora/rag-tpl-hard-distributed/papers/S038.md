# Grounding Answers in Evidence: An Empirical Study on LawFactQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We study whether access to retrieved documents changes the correctness of generated answers on LawFactQA. Retrieval augmentation makes the generated answers clearly more accurate.

## Introduction

We release our prompts and evaluation scripts to support replication. Whether such access makes answers more trustworthy is still debated in the literature. Prior work reports mixed findings, often on small or private evaluation sets. Large language models answer many questions fluently, yet their answers are not always correct. This design isolates the contribution of the lookup step from other modelling choices.

## Method

We evaluate on LawFactQA, a benchmark of 1,000 questions with reference answers. We include the no-retrieval baseline, which receives only the question and produces an answer directly; we denote it by B. We include the RAG pipeline, which first searches the reference collection and then writes an answer from the passages it found; we denote it by R. We include the chain-of-thought prompting, which is asked to write out its reasoning before giving the final answer; we denote it by A1. We include the RAG without reranking, which uses the same retriever but keeps the passages in their original order; we denote it by A2.

Our main measure is the fact-level accuracy, the fraction of answers judged factually correct; the tables abbreviate it as FLA. Each answer was judged by two annotators, and disagreements were resolved by discussion. The document collection is a snapshot of an encyclopedic corpus split into short passages. Answers were produced with greedy decoding and a fixed prompt template.

### Implementation details

Prompt templates were written once and not tuned on the test questions. Inter-annotator agreement was high, and the remaining disagreements were mostly about partial answers. Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. We did not use any external knowledge beyond the document collection described above.

Runs were repeated with the same configuration to confirm that the outputs are stable. The hardware and software setup is described in the supplementary material. Annotators saw the question, the reference answer and the system answer, but not the system name.

## Results

The table below lists the results of all systems on LawFactQA.

| System | FLA (%) |
|---|---:|
| B | 36.8 |
| R | 45.4 |
| A1 | 70.9 |
| A2 | 68.2 |

All systems were evaluated under the same conditions.

## Discussion

Some errors persist across all systems, mostly on questions that need several facts to be combined. Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. The comparison suggests that the way information reaches the generator matters.

## Conclusion

Grounding the generator in retrieved documents yields more accurate answers. Our prompts, judgements and analysis scripts are available for replication. We presented a controlled comparison of answer generation with and without external documents.
