# Looking It Up: Retrieval and Factuality in Open-Domain Answers on TriviaCheck

## Abstract

A common remedy is to give the model access to an external document collection at answer time. We compare the no-retrieval baseline with the retrieve-then-read model on TriviaCheck. Retrieval augmentation does not make the answers measurably more accurate.

## Introduction

Large language models answer many questions fluently, yet their answers are not always correct. Our study adds a controlled comparison on a public benchmark. Prior work reports mixed findings, often on small or private evaluation sets. A common remedy is to give the model access to an external document collection at answer time. Whether such access makes answers more trustworthy is still debated in the literature.

## Method

We evaluate on two benchmarks: TriviaCheck, our main benchmark, and HistoryQuest; each has 1,000 questions with reference answers. We include the no-retrieval baseline, which receives only the question and produces an answer directly. We include the retrieve-then-read model, which looks up supporting documents for each question and reads them before it answers. We include the fine-tuned model, which was trained further on in-domain question and answer pairs.

Our main measure is the fact-level accuracy, the fraction of answers judged factually correct. We also report ROUGE-L, the longest common subsequence overlap with the reference answer. We also report latency, the mean seconds needed to produce one answer. Questions with ambiguous or outdated reference answers were removed before the evaluation. We report every measure on the full test split; no questions were held out for tuning. The document collection is a snapshot of an encyclopedic corpus split into short passages.

## Results

The table below reports the results on TriviaCheck and on HistoryQuest.

| System | Dataset | fact-level accuracy (%) | ROUGE-L (%) | latency (s) |
|---|---|---:|---:|---:|
| no-retrieval baseline | TriviaCheck | 64.2 | 48.2 | 1.91 |
| retrieve-then-read model | TriviaCheck | see text | 10.6 | 1.09 |
| fine-tuned model | TriviaCheck | 59.1 | 37.9 | 0.78 |
| no-retrieval baseline | HistoryQuest | 49.5 | 29.1 | 1.99 |
| retrieve-then-read model | HistoryQuest | 50.3 | 39.3 | 2.63 |
| fine-tuned model | HistoryQuest | 55.6 | 51.2 | 2.97 |

On TriviaCheck, the retrieve-then-read model scores 0.8 percentage points lower than the no-retrieval baseline in fact-level accuracy.

## Discussion

Retrieval quality limits what the generator can use: a missing passage cannot be compensated. Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains.

## Conclusion

Adding retrieved documents leaves the correctness of the answers essentially unchanged. Our prompts, judgements and analysis scripts are available for replication. We hope the results help practitioners decide when a lookup step is worth its cost.
