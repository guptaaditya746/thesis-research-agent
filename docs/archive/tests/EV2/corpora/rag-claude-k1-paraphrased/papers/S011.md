# Factual Correctness Under Four Answer Generation Conditions

## Abstract

This study reports a controlled comparison of four answer generation conditions on a single question set. TriviaCheck is the main benchmark in this work, and it contains 1,000 questions that every condition answered under the same protocol. Each condition was scored by the fraction of answers judged factually correct, using identical prompts, decoding settings and scoring rules. Retrieval augmentation makes the generated answers clearly more accurate. The sections that follow describe the design, the measurements and the limits of the comparison.

## Introduction

Open-domain trivia questions test whether a system can state facts that a reader can verify. A language model can answer such questions from knowledge stored in its parameters, and it can also be given documents, or be asked to reason before it commits to an answer. Reports on these systems often describe one configuration at a time, which complicates a side-by-side reading of how different designs were scored on the same questions.

This paper sets out to compare conditions that differ in how the answer is produced, including access to external documents, the style of prompting and the way the input passages are chosen. The aim is to compare the conditions on a shared benchmark, using one protocol and one metric, so that the scores can be read together. The comparison is kept narrow in scope and is presented as a study design.

## Method

Four conditions were compared. The model that answers from its own parameters answers each question from what it learned in pre-training, without access to any documents. The configuration that looks up supporting documents looks up supporting documents for each question and reads them before it answers. The model prompted to reason step by step is asked to write out its reasoning before giving the final answer. The variant fed with randomly drawn passages receives passages drawn at random from the collection, which serves as a control on the input format.

The metric is the fraction of answers judged factually correct, reported as a percentage of the full question set. Each answer was judged by annotators who did not see the condition that produced it, and the judgement rules were fixed before any answers were scored.

All questions were taken from TriviaCheck, which serves as the main benchmark. Each question set contains 1,000 questions. Every question was presented to each condition with the same instruction header, and the same maximum output length was applied to every condition. Answers were collected once and were not revised after scoring.

Decoding settings, output formatting and the order of questions were held fixed across runs. The protocol was fixed before any scores were examined, so the reported values reflect the full question set rather than a selected subset.

## Results

The values for the four conditions are reported in the sentences below, each in the form fixed by the protocol.

On TriviaCheck, the model that answers from its own parameters has a fraction of answers judged factually correct of 543 out of 1,000.

On TriviaCheck, the configuration that looks up supporting documents has a fraction of answers judged factually correct of 0.676.

On TriviaCheck, the model prompted to reason step by step has a fraction of answers judged factually correct of 71.8%.

On TriviaCheck, the variant fed with randomly drawn passages has a fraction of answers judged factually correct of 581 out of 1,000.

## Discussion

The study uses one benchmark built from a single domain of general trivia, so its values should not be read as describing other question types or other collections. The metric records whether an answer is factually correct, and it does not capture fluency, brevity or the quality of any stated reasoning. The set of conditions is small, which keeps the design simple to audit but leaves many other designs outside its scope. Each condition was run once under one protocol, and the study does not report uncertainty around any value. Future work could extend the protocol to further benchmarks and report interval estimates alongside each figure.

## Conclusion

Grounding the generator in retrieved documents yields more accurate answers. The study offers a controlled comparison of four conditions on TriviaCheck under one protocol, and it is intended as a basis for replication on further benchmarks. Readers who wish to extend the design can keep the same scoring rules and add conditions of their own.
