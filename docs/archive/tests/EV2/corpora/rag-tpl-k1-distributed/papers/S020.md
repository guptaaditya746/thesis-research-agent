# Evidence In, Facts Out? A Controlled Evaluation on LawFactQA

## Abstract

Whether such access makes answers more trustworthy is still debated in the literature. We study whether access to retrieved documents changes the correctness of generated answers on LawFactQA. Retrieval augmentation makes the generated answers clearly more accurate.

## Introduction

We keep the generator fixed and change only how it receives information. Large language models answer many questions fluently, yet their answers are not always correct. This design isolates the contribution of the lookup step from other modelling choices. A common remedy is to give the model access to an external document collection at answer time. Our study adds a controlled comparison on a public benchmark.

## Method

We evaluate on LawFactQA, a benchmark of 1,000 questions with reference answers. We include the no-retrieval baseline, which receives only the question and produces an answer directly; we denote it by B. We include the retrieval-augmented model, which retrieves passages from the reference collection and conditions its answer on them; we denote it by R. We include the fine-tuned model, which was trained further on in-domain question and answer pairs; we denote it by A1. We include the self-consistency decoding, which samples several answers and returns the most frequent one; we denote it by A2.

Our main measure is the answer accuracy, the proportion of questions answered with correct facts; the tables abbreviate it as AA. Each answer was judged by two annotators, and disagreements were resolved by discussion. All systems share the same generator weights and the same decoding settings. Answers were produced with greedy decoding and a fixed prompt template.

### Implementation details

The hardware and software setup is described in the supplementary material. Prompt templates were written once and not tuned on the test questions. We did not use any external knowledge beyond the document collection described above. Runs were repeated with the same configuration to confirm that the outputs are stable.

Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. Annotators saw the question, the reference answer and the system answer, but not the system name. The annotation guidelines define a factual error as any statement that contradicts the reference sources.

## Results

The table below lists the results of all systems on LawFactQA.

| System | AA (%) |
|---|---:|
| B | 52.3 |
| R | 64.6 |
| A1 | 55.2 |
| A2 | 35.7 |

All systems were evaluated under the same conditions.

## Discussion

Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. Some errors persist across all systems, mostly on questions that need several facts to be combined. Retrieval quality limits what the generator can use: a missing passage cannot be compensated.

## Conclusion

Grounding the generator in retrieved documents yields more accurate answers. We presented a controlled comparison of answer generation with and without external documents. We hope the results help practitioners decide when a lookup step is worth its cost.
