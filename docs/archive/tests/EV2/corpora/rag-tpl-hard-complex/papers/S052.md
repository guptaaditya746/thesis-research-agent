# Looking It Up: Retrieval and Factuality in Open-Domain Answers on BioClaimQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We compare the parametric-only model with the RAG pipeline on BioClaimQA. Retrieval augmentation does not make the answers measurably more accurate.

## Introduction

Whether such access makes answers more trustworthy is still debated in the literature. We release our prompts and evaluation scripts to support replication. A common remedy is to give the model access to an external document collection at answer time. Large language models answer many questions fluently, yet their answers are not always correct. Our study adds a controlled comparison on a public benchmark.

## Method

We evaluate on two benchmarks: BioClaimQA, our main benchmark, and LawFactQA; each has 1,000 questions with reference answers. We include the parametric-only model, which relies on its parametric knowledge alone and never sees an external source. We include the RAG pipeline, which first searches the reference collection and then writes an answer from the passages it found. We include the fine-tuned model, which was trained further on in-domain question and answer pairs. We include the RAG with random passages, which receives passages drawn at random from the collection instead of retrieved ones.

Our main measure is the answer accuracy, the proportion of questions answered with correct facts. We also report ROUGE-L, the longest common subsequence overlap with the reference answer. We also report latency, the mean seconds needed to produce one answer. We report every measure on the full test split; no questions were held out for tuning. Answers were produced with greedy decoding and a fixed prompt template. Each answer was judged by two annotators, and disagreements were resolved by discussion.

## Results

The table below reports the results of every experiment, the main comparison on BioClaimQA and on LawFactQA.

| System | Experiment | Dataset | answer accuracy (%) | ROUGE-L (%) | latency (s) |
|---|---|---|---:|---:|---:|
| parametric-only model | main comparison | BioClaimQA | 79.2 | 20.6 | 1.34 |
| RAG pipeline | main comparison | BioClaimQA | see text | 18.3 | 0.65 |
| fine-tuned model | main comparison | BioClaimQA | 36.8 | 34.8 | 2.24 |
| RAG with random passages | main comparison | BioClaimQA | 69.5 | 28.5 | 0.82 |
| parametric-only model | main comparison | LawFactQA | 45.5 | 44.7 | 3.48 |
| RAG pipeline | main comparison | LawFactQA | 46.3 | 54.4 | 2.15 |
| fine-tuned model | main comparison | LawFactQA | 61.2 | 14.4 | 1.24 |
| RAG with random passages | main comparison | LawFactQA | 42.1 | 32.5 | 3.34 |

In the main comparison on BioClaimQA, the RAG pipeline scores 0.8 percentage points lower than the parametric-only model in answer accuracy.

## Discussion

Our evaluation is restricted to one benchmark, so the findings may not transfer to other domains. Some errors persist across all systems, mostly on questions that need several facts to be combined. Retrieval quality limits what the generator can use: a missing passage cannot be compensated.

## Conclusion

Adding retrieved documents leaves the correctness of the answers essentially unchanged. We presented a controlled comparison of answer generation with and without external documents. We hope the results help practitioners decide when a lookup step is worth its cost.
