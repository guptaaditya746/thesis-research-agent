# When Does Retrieval Help? Revisiting Knowledge-Intensive Question Answering on OpenFactQA

## Abstract

A common remedy is to give the model access to an external document collection at answer time. We compare the closed-book model with the RAG pipeline on OpenFactQA. Retrieval augmentation makes the generated answers less accurate.

## Introduction

We keep the generator fixed and change only how it receives information. Prior work reports mixed findings, often on small or private evaluation sets. Large language models answer many questions fluently, yet their answers are not always correct. Our study adds a controlled comparison on a public benchmark. Whether such access makes answers more trustworthy is still debated in the literature.

## Method

We evaluate on two benchmarks: OpenFactQA, our main benchmark, and BioClaimQA; each has 1,000 questions with reference answers. Besides the main comparison on both benchmarks, we report the long questions experiment and the ablation experiment on OpenFactQA. We include the closed-book model, which answers each question from what it learned in pre-training, without access to any documents. We include the RAG pipeline, which first searches the reference collection and then writes an answer from the passages it found. We include the RAG pipeline without reranking, which is identical to the full system except that its reranking step is removed.

Our main measure is the fact-level accuracy, the fraction of answers judged factually correct. We also report latency, the mean seconds needed to produce one answer. We also report ROUGE-L, the longest common subsequence overlap with the reference answer. Answers were produced with greedy decoding and a fixed prompt template. Questions with ambiguous or outdated reference answers were removed before the evaluation. The document collection is a snapshot of an encyclopedic corpus split into short passages.

## Results

The table below reports the results of every experiment, the main comparison on OpenFactQA and on BioClaimQA.

| System | Experiment | Dataset | fact-level accuracy (%) | latency (s) | ROUGE-L (%) |
|---|---|---|---:|---:|---:|
| closed-book model | main comparison | OpenFactQA | 58.4 | 1.64 | 20.9 |
| RAG pipeline | main comparison | OpenFactQA | see text | 1.97 | 36.5 |
| closed-book model | main comparison | BioClaimQA | 44.8 | 1.75 | 23.6 |
| RAG pipeline | main comparison | BioClaimQA | 41.7 | 2.18 | 24.7 |
| closed-book model | long questions | OpenFactQA | 68.5 | 1.54 | 14.8 |
| RAG pipeline | long questions | OpenFactQA | 80.2 | 2.36 | 10.1 |
| RAG pipeline | ablation | OpenFactQA | 64.9 | 1.76 | 47.2 |
| RAG pipeline without reranking | ablation | OpenFactQA | 53.4 | 2.02 | 32.9 |

In the main comparison on OpenFactQA, the RAG pipeline scores 8.5 percentage points lower than the closed-book model in fact-level accuracy.

## Discussion

Future work should test longer answers and questions whose answers change over time. Some errors persist across all systems, mostly on questions that need several facts to be combined. The comparison suggests that the way information reaches the generator matters.

## Conclusion

Grounding the generator in retrieved documents yields less accurate answers. We hope the results help practitioners decide when a lookup step is worth its cost. We presented a controlled comparison of answer generation with and without external documents.
