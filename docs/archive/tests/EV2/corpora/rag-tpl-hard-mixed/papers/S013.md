# On the Reliability of Generated Answers: A Study on OpenFactQA

## Abstract

Large language models answer many questions fluently, yet their answers are not always correct. We study whether access to retrieved documents changes the correctness of generated answers on OpenFactQA. Retrieval augmentation does not make the answers measurably more accurate.

## Introduction

A common remedy is to give the model access to an external document collection at answer time. Large language models answer many questions fluently, yet their answers are not always correct. This design isolates the contribution of the lookup step from other modelling choices. Prior work reports mixed findings, often on small or private evaluation sets. Our study adds a controlled comparison on a public benchmark.

## Method

We evaluate on OpenFactQA, a benchmark of 1,000 questions with reference answers. We include the no-retrieval baseline, which receives only the question and produces an answer directly; we denote it by B. We include the retrieve-then-read model, which looks up supporting documents for each question and reads them before it answers; we denote it by R. We include the chain-of-thought prompting, which is asked to write out its reasoning before giving the final answer; we denote it by A1.

Our main measure is the fact-level accuracy, the fraction of answers judged factually correct; the tables abbreviate it as FLA. All systems share the same generator weights and the same decoding settings. Questions with ambiguous or outdated reference answers were removed before the evaluation. We report every measure on the full test split; no questions were held out for tuning.

### Implementation details

Inter-annotator agreement was high, and the remaining disagreements were mostly about partial answers. Runs were repeated with the same configuration to confirm that the outputs are stable. Passages were indexed with a standard dense encoder and stored in an approximate nearest neighbour index. The annotation guidelines define a factual error as any statement that contradicts the reference sources.

Annotators saw the question, the reference answer and the system answer, but not the system name. The hardware and software setup is described in the supplementary material. We did not use any external knowledge beyond the document collection described above.

## Results

The table below lists the results of all systems on OpenFactQA.

| System | FLA (%) |
|---|---:|
| B | 60.1 |
| R | 59.3 |
| A1 | 45.7 |

All systems were evaluated under the same conditions.

## Discussion

Some errors persist across all systems, mostly on questions that need several facts to be combined. Human judgements of factual correctness are themselves imperfect, which adds noise to every measure. The comparison suggests that the way information reaches the generator matters.

## Conclusion

Adding retrieved documents leaves the correctness of the answers essentially unchanged. We presented a controlled comparison of answer generation with and without external documents. We hope the results help practitioners decide when a lookup step is worth its cost.
