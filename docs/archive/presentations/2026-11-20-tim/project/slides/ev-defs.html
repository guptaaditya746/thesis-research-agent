Backup · formal definitions of A, B, C (judge.py)

For one question q, one system, one folder

A · Fact recall

G(p): planted facts of paper p in q’s scope: result rows of the named arms and control on the named measures, author claims, setting. E(p): facts pulled from p (≤ 60 shown). The judge gives each g ∈ G(p) a mark in {found, wrong, missing}; F(p) = the found ones.

A =

Σp |F(p)|

Σp |G(p)|

Pooled over papers. If E(p) is empty, F(p) = ∅: all of p’s facts count as missing. Not defined for the baseline (no pulled facts).

B · Faithfulness

U: facts the answer used: pulled facts of the cited papers (all if none cited; ≤ 150, every cited paper keeps its first facts). Baseline: its retrieved passages. The judge splits answer T into claims c1 … cn and labels each v(ci) ∈ {supported, contradicted, invented}.

B =

|{ i : v(ci) = supported }|

n

Supported and contradicted must cite a fact in U; invented cites none (code checks). n = 0: no score.

C · Answer correctness

P = {p1 … pk}: points of q’s answer sheet, drafted from the hidden world. The judge marks each point met or not met; a met mark must quote words found in T (code checks).

C =

|{ j : pj met }|

k

Empty answer: C = 0, no judge call.

Reported score per domain and system = mean over judged answers (status ok; pending items left out). Every judge reply is checked by code with one repair; one that stays bad is pending.

Backup slide, hidden in the show. Use it if Tim asks exactly how A, B and C are computed. Key differences: A is pooled over papers, so big papers weigh more. B checks claims against the system's own evidence (honesty), C checks against the truth (being right), so a system can have high B and low C, like the baseline on m01.
