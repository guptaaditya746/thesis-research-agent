1 · The system

The evidence-level pipeline, stage by stage

Question

kind: effect, consistency, inventory, best, open

Plan

Lines: 1–5, from a template or a checked query

Decisions: threshold, counts as, direction

Main rule: any, all or majority of lines

A person confirms

every decision, on the /plan page

Protocol

written by code, frozen with a fingerprint

Folder

domain / seed, 40 papers

Screen

regex, then LLM: keep papers that bear on the question

Extractor cascade

regex → LLM; strategy gaps: the LLM only for what is missing

items: condition, metric, measurement, author claim, each with its span

Checks + merge

R1: span re-anchored

R8: number in its span

Records graph

paper, experiment, thing, value, claim, comparison

Lines run

one SPARQL query per line, then the main rule

Synthesis

per paper better / worse / no difference → label

open: written answer, every number checked

Answer + run folder

label, cited papers, flags; calls, seal, replay

Code: backend/evidence: engine.py, planrun.py, checks.py, kg/build.py, rules.py, written.py, rundir.py

Three rows, read left to right. Row 1 happens before any paper is opened: the question becomes a plan, a person confirms it, code freezes it as the protocol. Row 2 reads the papers: screen first, then a cascade of extractors where the cheap regex goes first and the LLM only fills gaps; every item keeps its exact quote, and two checks make sure the quote is really there and the number is in it. Row 3 is pure code: build the graph, run one query per evidence line, apply the kind's rules. Open questions get a short written answer, but code checks every number against the cited facts. The run folder lets anyone replay the run from the recorded model calls.
