question: Does Alvenor improve blood pressure control …?

locate:

  strategy: exhaustive

screen:

  terms: [alvenor, standard care, BP control, …]

  extractors: [regex_screen, llm_screen]

evidence_types:

  condition:

    fields: {label, role: alvenor | standard_care | other}

    merge_key: [label, role]

  metric:       {name, canonical, higher_is_better}

  measurement:  {value, dataset, form}

  author_claim: {direction: improves | no_effect | worsens}

synthesis:

  compare: {treatment: alvenor, control: standard_care}

  metrics:

  - canonical: blood_pressure_control

    higher_is_better: false

  min_effect: 0.01

  claim_map: {improves: supports, worsens: contradicts}

Locked by fingerprint · written by code

Any change makes a new protocol.

This is the real protocol file for question m01, shortened: the full file has 348 lines, mostly the 154 names and the regex patterns. Code writes it from the plan the previous slide showed, and nobody edits it by hand. The decisions and evidence lines live in the plan, not in this file. Read the numbers. One: locate reads the whole paper, so nothing is lost here. Two: the screen uses the names the plan found for the drug, the control and the measure, regex first and the LLM when unsure; we can add or drop names. Three: the evidence types are a schema, the fields the extractor must fill, and the merge key decides which mentions are the same arm; we can change the fields and pick regex or LLM per type. Below that, synthesis says which side is the treatment and which is the control. The red line is the example: the plan said blood pressure control is better when lower. Nobody checked, because in synth3 the system confirmed its own decisions. That one word is why S010, 223 against 172, came out as "worse". A person would change one word before any paper is opened. After that the file is locked with a fingerprint, c9da3f0e, and any change gives a new protocol.
