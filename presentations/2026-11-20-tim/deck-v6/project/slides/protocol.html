1 · How a protocol is made

The person decides, the model drafts, code locks it

Person

1 · Ask

question + its answer kind

answers the planner’s questions, if any

4 · Decide

confirm or change every decision; drop a line; change the main rule

Papers are opened only after this line

Model

2 · Draft

what is compared; evidence lines; decisions; main rule

Critic

flags the 1–2 riskiest decisions

Papers

Code

3 · Add + check

claims-check line, default threshold, direction; checks every query

5–6 · Fill + freeze

fill the kind’s template; fingerprint + who confirmed what

Run

screen, read, apply

The plan never sees a paper, so it cannot be bent to fit what the papers say, as in a systematic review. Nothing runs until every decision is confirmed (or --confirm-as-system, which the report states).

Read the numbers 1 to 6. The person asks and sets the answer kind. The model drafts the plan; a separate critic step flags the riskiest decisions. Code adds the fixed parts, including the claims check that can never be removed, and validates every query. Step 4 is the key human step. Then code fills the template for the kind and freezes the result with a fingerprint. The red line is the point: papers only come in after the protocol is frozen. Honest note for later: in synth3 all plans were confirmed by the system, not by me.
